# Readhold code guidebook

A map of the code for someone who will read or change it. For how to *use* the app, see `docs/GUIDE.md`. For the rules every change must keep, see the list of invariants at the end of each chapter in `docs/code/`.

## Summary

Readhold is a local-first study app: a reader for papers and articles, lecture notebooks, goals, tasks, notes, a journal and spaced review. It runs entirely on one computer and connects to nothing by itself. The only connection it can make is to the AI model the user chose, and only while AI is switched on (it is off by default).

- **Shape.** A Python server (FastAPI) on `127.0.0.1` serves a single-page front end written in TypeScript. A desktop window (pywebview) or the browser shows it. All data is in one SQLite file.
- **Size.** About 14,300 lines of Python in 65 files, about 14,200 lines of TypeScript in 58 files, one stylesheet (2,064 lines), 21 database migrations, 46 tables (two of them no longer used, see section 5) and one full-text index, 210 routes, 12 themes. (Measured on 2026-11-26, after milestone 5.3: `.py` files under `readhold/` (14,306 lines; since 4.5 `ai/where.py`, and Phase 5 added `trash.py`, `tidy.py`, `ai/tidy.py` and `ai/chat.py`), `.ts` files under `web/src/` (14,178 lines; Phase 5 added `trash.ts`, `views/tidy.ts` and `views/planchat.ts`), the route decorators `@app.get`, `post`, `put`, `patch` and `delete` (Phase 5 added 11: two in `trash.py`, `GET /api/timer/recent`, four in `tidy.py`, `POST /api/tidy/suggest` and three Plan chat routes; not counted: the one `@app.middleware` and the two `@app.exception_handler`s), `CREATE TABLE` statements in the migrations (`0020` and `0021` only add columns; Phase 4 and Phase 5 added no migration).)
- **Back end.** `readhold/server.py` builds the app, guards every request and holds the reader's routes. Each other feature is one module with a `register(app, db)` function.
- **Front end.** `web/src/main.ts` is a hash router. Each page is a function in `web/src/views/`. There is no framework: pages build DOM nodes with one helper, `h()`.
- **No feature needs an AI model.** Text structure, density, definitions, similar notes, suggestions, related documents, suggested tags and search are all rule-based or counted from words. An AI assistant is being built to `docs/ai/PLAN.md`: its Phase 0 (foundations, no AI) is built, and so is all of Phase 1 (milestones 1.1, 1.2, 1.2b, 1.3, 1.4 and 1.5): the package `readhold/ai/` with the LLM port, a local and a cloud adapter, per-task profiles, key storage, the AI log, the off switch and the guardrails every feature goes through (section 4.5), and three features that call a model, each only when the reader presses its button: the Resume briefing (`ai/resume.py`; its facts, "Where you left off", need no model), Explain selection (`ai/explain.py`) and the Document digest (`ai/digest.py`; its outline and reading time need no model; the summary is map-reduce in a background job). AI is off by default. Of Phase 2, milestones 2.1, 2.2, 2.3 and 2.4 are built: 2.1, Quote and anchor verification, one checker for every quote (`guard.quote_in`, `guard.verify_citations`) and one shared set of fake citations that every feature must catch (`tests/test_ai_citations.py`); 2.2, Ask this document (`ai/ask.py`), the fourth feature: the reader's Ask tab finds the passages that match a question without a model, and with AI on a model answers from the best-matching sections only, with checked quotes, or says "not found"; 2.3, Ask my library (`ai/library.py`), the fifth feature and the plan's one bounded agent loop: the *Ask your library* box on the Documents tab finds the passages and notes that match a question without a model, and with AI on a model starts from them, may search again or read more of one source (two read-only tools), at most 3 steps, and answers with checked quotes from documents and notes, or says "not found in your library"; 2.4, Study notes writer and flashcards (`ai/notes.py`), the sixth feature: the reader's **Study notes** button points to the summary sheet without a model, and with AI on a model drafts a quiz, flashcards or notes from the reader's highlights or one section, each item resting on a quote checked against the text as sent; nothing is saved until the reader keeps items, which go to a labelled note or to Review as `ai` cards, once. And of Phase 3, 3.1, Reading plan: `readhold/readplan.py` schedules without a model (the reader's order and levels, minutes a day, a deadline; no day over the minutes, nothing past the deadline, what does not fit named) and adds the plan as tasks with one-step Undo; with AI on `ai/plan.py`, the seventh feature, suggests the order and levels from sizes, section titles and openings, each reason resting on a checked quote or labelled a guess, and changes nothing until the reader uses it; 3.2, Brainstorm (`ai/brainstorm.py`), the eighth feature: the brainstorm sheet of Think works without a model, and with AI on a model writes ideas in three samples from three angles (diverge) and a critic call groups and ranks them (converge), each idea resting on its own checked quotes from the reader's reading or notes; since 2026-11-26 (the owner's decision) the ideas that rest on checked quotes go straight into the reader's sheet when the reader asks for them, each as its own section, with Undo; and 3.3, Organize library and related documents: `readhold/organize.py` gives documents tags that are also collections, related documents by TF-IDF without embeddings, and tags suggested by code; with AI on `ai/organize.py`, the ninth feature, suggests tags (the reader's own first, at most two new) and related documents from the list code made, each checked, and changes nothing until the reader adds a tag. Phase 3 is done. Of Phase 4, 4.1, Evaluation harness, is built: `uv run python -m readhold.eval` (`readhold/eval/`) runs the nine features over a fixed sample set in a throwaway folder, through their own routes, and prints one table of scores; `--stand-in` runs it on a fake model (section 4.5); and 4.2, "Why did it say this?" (`ai/why.py`, `web/src/views/why.ts`): a link beside the label of every AI text opens a panel that traces it to its model calls, the guards' checks, the sources each call was sent (named from the anchors `guard.pack` now records in `ai_log`, never their text) and each prompt word for word; it calls no model. 4.3, Full red-team suite in CI: `tests/test_redteam.py` runs each row of the plan's section 6.9 end to end, and `.github/workflows/ci.yml` runs it first on every push and pull request (Windows and Linux; it has not run yet, as the repository is not on GitHub); row 7 differs from the plan (a 500-page document is refused, not map-reduced; for the owner to decide). 4.4, Privacy controls (`ai/privacy.py`, `web/src/aipreview.ts`): `#private` items, and your own text that copies them, never leave this computer; `#cloud`-only is the opt-in alternative; the send preview (428, then the same request again with a one-time `X-AI-Approve` token); the AI log kept 1, 7 or 30 days; Clear AI history (the separate Export AI data was removed on 2026-11-26: Export everything holds the kept AI results, and the AI log is in no export). 4.5, Security review: the threat model re-checked (plan section 6.1a) and the review's fixes (a "local" server on another computer gets every cloud rule, writes only from the app's own origin, caps on PDF pages, code lines and rendered pages, key-shaped values refused in every setting, a 422 that never echoes its input, `bind`, three more response headers). **Phase 4 is done.** Phase 5, "Everyday control", was added to the plan on 2026-11-26 from the parking lot, and is built: 5.1, Delete on everything (`readhold/trash.py`, `web/src/trash.ts`, no model): one route pair, `DELETE /api/items/{kind}/{id}` and `POST …/restore`, for an allowlist of ten kinds, each record's linked rows going and coming back with it; 5.2, Tidy: `readhold/tidy.py` gives hints for what a task lacks and the fixes code is sure of, for tasks, notes and routines, without a model, and with AI on `ai/tidy.py`, the tenth feature, proposes a rewrite, checked, with every new word listed; 5.3, Plan chat (`ai/chat.py`), the eleventh feature and the plan's first free-text one: a model drafts at most 12 tasks from what the reader types, each checked by code, and only one click adds them, as a batch with Undo. **Phase 5 is done.** 5.4, Note chat (`ai/notechat.py`), added on request the same day, is the twelfth feature: in a note, a model rewrites the note or writes text for its end from what the reader types, checked like Tidy's note, and only **Use this** or **Add to the note** changes the note, with Undo. Tidy, Plan chat and Note chat show no quote (`NO_QUOTES` in `tests/test_ai_citations.py`), and the evaluation harness runs them too (since 2026-11-26; sample set version 3 adds the note chat). Before publishing: a fresh git history (the LICENSE (MIT), `THIRD_PARTY_NOTICES.md` and the actions pinned by commit SHA are done, 2026-11-26).
- **Tests.** `uv run pytest` runs 920 tests (918 pass and 2 are skipped, measured on 2026-11-26 after milestone 5.4, in 109 s: the digest's "not sent" case, on purpose, and the real-files test when `tests/fixtures/real/` is empty; 628 test functions in 45 files, some run once per theme or per case). They cover the parsers, the API, the theme rules, the network rule, the reading plan's scheduler, document tags and related documents, the AI port (against a fake model server), the AI guardrails (attack files that must fail safely), the Resume briefing, Explain selection, the Document digest, Ask this document, Ask my library, Study notes, the reading plan's suggestion, Brainstorm and Organize (against the same fake server; no test uses a real model), one set of fake citations run against the checker and every feature, "Why did it say this?", the evaluation harness (its scores, and a whole run on its stand-in model), the red-team suite (every row of the plan's section 6.9, end to end), the privacy controls, the fixes of the security review, delete and Undo on every kind of record, Tidy (with and without a model), Plan chat and Note chat. CI runs the red-team suite first, then every test, then the front-end build, on Windows and Linux. The front end has type checks only.
- **Four rules shape most of the code:** nothing leaves the machine except the text of an AI call the user switched on, imported text is never treated as HTML, every edit is saved at once, and every schema change is a numbered migration.

## 1. Run, build, test

| What | Command |
|---|---|
| Start in a desktop window | `uv run python -m readhold` |
| Start in the browser | `uv run python -m readhold --browser` |
| Server only (development) | `uv run python -m readhold --serve --port 8765 --token devtoken`, then open `/auth?token=devtoken` |

Set `READHOLD_HOME` to keep data somewhere other than the project folder. This is how to try changes on a copy of your data.

**CI.** `.github/workflows/ci.yml`, on every push and pull request, on `windows-latest`, `ubuntu-latest` and `macos-latest`: `uv sync --locked`, the red-team suite, `uv run pytest -q`, then `npm ci` and `npm run build` in `web/` (Node 24). `permissions: contents: read`, `persist-credentials: false`, `timeout-minutes: 30`, no secrets. Each action is pinned to a release's full commit SHA. No Dependabot version updates (removed on 2026-11-27): the versions stay as locked. The workflow first ran on 2026-11-27 and passed.

## 3. How a request flows

1. `readhold/__main__.py` binds a socket on `127.0.0.1` (`bind`: a free port, or `--port`), makes a random session token, opens the database, and starts uvicorn on that same socket, so the port is never free in between.
2. The window opens `/auth?token=…`. The server sets an http-only cookie and redirects to `/`.
3. `index.html` loads `app.js`. `main.ts` calls `loadState()` (settings and themes), applies the theme, and routes on the URL hash.
4. A page function calls `api.get/post/patch/put/del` (`web/src/api.ts`), which talks to `/api/...`.
5. Every request passes the `guard` middleware in `server.py`: Host header check, token check, for a write the origin check (`Origin` must be the app's own, `Sec-Fetch-Site` `same-origin` or `none`, else 403), `ai.privacy.approve` with the `X-AI-Approve` header (a one-time approval of a send preview, for this request only), then security headers on the response.
6. The route reads or writes through the `DB` helper and returns JSON.

**2.1 Quote and anchor verification** ("Fake citations in test outputs are always caught"). Already there before 2.1: the plan's "Quote verification" and "Anchor verification" (section 6.3) are `guard.quote_in` and `guard.verify_citations`; each feature checks a quote against exactly the text it sent, then through `verify_citations`; the three statuses `verified`, `partly`, `unverified`; an invented quote and a missing anchor tested per feature and in `tests/test_ai_guard.py`. What 2.1 added: `verify_citations` also needs the cited sentence's paragraph and section to be live, and looks at no more than `MAX_CITATIONS` (40) citations of one answer (the rest count as removed); `_plain`, the form both sides are compared in, keeps what changes a meaning (a hyphen or apostrophe between two letters is part of the word, so "significant" is not in "non-significant" and a quote must keep "top-k" as written; `71.2` is one token, not `71 2` or `712`; a comma between digits is a decimal mark, except a thousands comma, which is left out, so `1,000` is `1000` and `1.000` is another number; `-3` is "minus 3", also with U+2212, a superscript minus, an en dash, after a full stop or as `- 3`, but `3 - 4` is a range; `%` is "percent"); a quote is matched on whole words (`word_in`), so it cannot begin or end inside a word or a number; Explain's term check and the digest's keyword check use the same form and `word_in` (a keyword that is only a sign word or has no letter is dropped); and `tests/test_ai_citations.py`, one set of fake citations (`FAKES`) run against the checker and against every feature through its route, plus a registry test (Python's `ast`) that fails when a module under `readhold/` calls `guard.ask` under any name, or `port.complete(` directly, and is not in the file's `FEATURES` (`guard`, `api` for Test connection and `port` are the allowed direct callers, `DIRECT_CALLERS`). Decided by the owner on 2026-11-25: an answer with nothing verified stays labelled "unverified", not hidden as the plan's section 8 says (the reason is recorded under that table in `docs/ai/PLAN.md`). Not built: `verify_citations` does not take `note:<id>` anchors (2.3, Ask my library, the one feature that cites notes, checks a note quote itself in `library._citation`: in the note's text as sent and as it is now); the plan's page and character offsets are not used: an anchor is a document id and a sentence `ord`, which is never renumbered; **no page number is stored** for a PDF sentence (the parser knows each block's page and drops it), so a citation can open the sentence but cannot name its page. The whole-word match, the joined words, the thousands comma and the minus rules were found by a review of 2.1 and fixed right after. Still open: a quote may run across sentences and paragraphs of one section (allowed on purpose: the words are real and in order, and quoting two sentences is legitimate); `x-1` and `x − 1` do not match (a hyphen after a letter is not a minus, a typographic minus is); `1 000` with a space does not match `1,000`; the fake model server in the tests tells features apart by the wording of their prompts; Explain's check of a selection against a formula drawn in the browser is not verified. The full description is in [chapter 3, section 7b](code/03-backend-plan-notes-search-think.md).

What the guard adds for a feature that calls `guard.ask`:

| Guard | What it does |
|---|---|
| Cleaning (`sanitize`) | Removes invisible and control characters and puts the text in NFC. U+200C and U+200D are kept (Persian, Arabic and Indic words need them) |
| Fencing (`pack`) | Each source goes inside `<source anchor="…" trust="imported\|yours\|model">` tags (`model`: text a model wrote, read by another call; only the brainstorm critic uses it), with `SYSTEM_RULE` in the system text: source text is data, never instructions. A source cannot close its own fence (`_defuse`: `<source`, `<question`, `<system` and `<assistant` in the text lose their `<`, also when spaces, slashes or invisible joiners sit in between) |
| Budgets | `BUDGETS`: characters of source text per feature (6,000 for `explain` to 24,000 for `ask` and `library`), a total across the sources (`_shares`): when everything fits nothing is cut; otherwise the shorter sources stay whole and the longer ones share what is left equally, each cut at its end with ` […]` (`trimmed`). | Rules for text that leaves this computer (cloud mode, or since 4.5 a "local" server elsewhere) | Secrets, e-mail addresses and phone numbers redacted; a file of secrets by its name (`.env`, `id_rsa`, `*.pem`, `*.tfvars`, or a secret word such as `secrets`, `credentials`, `api_key`, `token` in the name of a file that is not prose) is refused with `Blocked` (Ask my library and Brainstorm leave such a file out before they pack, and count it, so it is never refused there; Organize does not name such a document among its candidates) |

Known limits, in short (the full list is in chapter 3, section 7b, and chapter 1, section 9.3): white PDF text is kept, because it cannot be told from white text on a coloured band; it is flagged and always fenced. Text hidden in other ways (behind a picture, in a form, render mode 3) is not detected. Order-like text in a legitimate paper about prompt injection is flagged too. E-mail and phone redaction applies only to cloud calls. A file of secrets is judged by its name only. `aiText` is not used by any page yet. A verified quote is real text of the section, not proof that the answer follows from it, and it may run across sentences of that section (see 2.1 above).

| Step | What happens |
|---|---|
| The facts | `GET /api/documents/{doc_id}/digest` returns `{facts, ai: {mode}, digest, job}`: the outline (sections with at least one live sentence, each with its words, first sentence and `skipped` for a hidden section), the words of the sections that are not hidden, `wpm` and `minutes`; the kept digest for the current keys (AI on only) or `null`; the document's last job or `null`. The reader's **Digest** button opens it |
| The decision | The plan says "Import, or the Digest button". Only the button is built: on import a cloud model would receive every new document. A model is asked only by a job, which only `POST /api/documents/{doc_id}/digest` starts |
| The parts | `chunks`: live sentences of sections that are not hidden, grouped by section and packed into parts of whole sections up to `CHUNK` (6,000 characters); a longer section is cut between sentences (`<title> (continued)`); the target grows by `GROW` (1.25) up to `MAX_CHUNK` (14,000) until there are at most `MAX_CHUNKS` (40) parts, else `TooLong` (409). | The map step | One `guard.ask(port, db, "digest_map", …, [one source], budget="digest_map", schema=MapOut, call_id=…)` per part, one after the other. Each part summary is kept in `ai_results` (`feature` `digest_map`) under `results.key(map prompt hash, part body)` as soon as it is made; a part the model cannot summarise (`CouldNotGenerate`) is skipped and asked for again by **Ask again**, or by the next run when no digest was kept |
| The reduce step | One `guard.ask(port, db, "digest", …, sources, budget="digest", schema=DigestOut, call_id=…)` whose sources are, per part that has a summary, the section titles (at most `HEADER_TITLES`), the summary and the points with their checked quotes. **Never the document's sentences.** Each part gets an equal share of `guard.BUDGETS["digest"]`; whole points are left out before anything is cut, so a quote is never cut in half and the log says `trimmed: false`. Key ideas: a quote is kept only when it is in a part's text and `verify_citations` keeps it (it then carries the sentence to jump to). Keywords not in the document are dropped. `difficulty` is a `Literal` of three words. Status `verified`, `partly` or `unverified` |
| The kept result | One `digest` row in `ai_results` under `results.key(reduce prompt hash, every part key)`, inside `results.once`. `fresh: true` (**Ask again**) reuses every kept part summary and redoes the combining step (and any part that had none); the new row is inserted before the old one is hidden |
| The job | `Job` (`state` `running`/`done`/`failed`/`cancelled`, `step` `parts`/`combining`, `done`, `total`, `message`), one per document in the module dict `_jobs`, started by `start` under a lock in a daemon thread. Stop: `POST …/digest/cancel` sets `job.stop` and cancels the call in flight (`port.cancel(call_id)`). `_check` (Stop pressed, AI off, or the document removed) runs before every part, right before and right after each model call, and before and after the combining call, so an answer that arrives after Stop is not kept (`Stopped`, the job ends `cancelled`). Removing the document (`server.api_doc_delete`) and Clear AI history call `digest.stop`. Errors of the run end the job `failed` with the reason in `message` |
| Status codes | GET: 200, 404. POST: 200 (a kept digest, or a job), 404, 409 (AI off, also when a digest is kept; too long; no text to digest, `Nothing`), 422 (body). Cancel: 200 with `{cancelled: bool}`, 404 for an unknown document |

Its limits (chapter 3, section 7b, has the list, with what was reproduced): nothing was tried against a real model (the plan's check "a 40-page paper yields an accurate outline" is about the parser's outline, which needs none; summary quality is open); a structure edit made during a run (a section hidden or renamed) is not seen by that run; a skipped part is retried only by **Ask again**, or when no digest was kept; a structure edit hides the digest instead of marking it old (the old rows stay, unused); a restart forgets the job (the dialog shows **Digest with AI**, not **Go on**; going on still works); the keys leave out the model and the profile; the front end has no automated tests.

Ask this document (milestone 2.2), in short:

| Step | What happens |
|---|---|
| The passages | `GET /api/documents/{doc_id}/ask?q=` returns `{passages, ai: {mode}}`: the sections of this document that match the question's words, best first (at most 5, each with the sentence to open at and a snippet). No model, no write; it works with AI off. The search words are `_terms` of the question: its numbers and acronyms (`RL`, `GPU`, `C++`) however short, then its longest other words, common words left out, at most 8; English words get a light cut ("gate" finds "gating"), other scripts are kept as written. | The decision | A model is asked only by `POST /api/documents/{doc_id}/ask`, which the page sends only from the **Ask** button (Enter in the box, or **Ask again**) while AI is on. | The context | `sources_for`: each matching section under `(Section: <title>)`, anchor `<doc>:<first ord>`, trust `imported`, in search order. | The call | `guard.ask(port, db, "ask", prompt.text, sources, budget="ask", question=q, schema=AskOut, prompt_version="ask_v1")`. | The check | `found` false or an empty answer: "not found", and whatever the model wrote beside it is dropped. Otherwise up to 4 citations, the same passage cited several times counting once: a quote is shown with ✓ only when it is in a source that was sent (`quote_in`, at least 4 words, whole words) and `verify_citations` keeps it, which gives the sentence to jump to. Status `verified`, `partly`, `unverified` (also with no citation) or `not_found`. Caps: answer 1,200, quote 400 characters |
| The kept result | One row in `ai_results` (`feature` `ask`) under `results.key(prompt hash, _cache_question(question), every source as sent)`, inside `results.once`. The same question in another case or spacing, or with or without a final `?`, `!` or `.`, on the same sections, is no new call (other punctuation counts: "C++" is not "C"); an edit of a matched section, or a change in which sections match, is a new key. `ask` raises `AIOff` before it looks. `fresh: true` (**Ask again**) asks again; the new row goes in first |
| Status codes | GET: 200, 404, 422 (an empty or too long question). Found later while updating these docs, and fixed: `guard.pack` cut every source to an equal share of the budget again, so with several hits a long section was cut from the start of its window and the sentence that matched could be left out, while its quote still counted as verified; now `pack` cuts only when the sources together are over the budget, and then the long ones first (`_shares`), so what `sources_for` built is sent as it is (`test_a_long_section_beside_short_ones_still_sends_the_matching_sentence`). Its limits (chapter 3, section 7b, has the list): hidden sections (the references) are searched and sent, on purpose ("who wrote …" is a fair question), and a jump into a collapsed one lands on the next paced sentence; the search is by words, not meaning, so synonyms and word forms beyond the light cut are not found, and the cut can widen a search ("time" also finds "timing"); when no section holds all the search words, any word is enough (up to 5 sections); the key leaves out the mode, the model and the profile; nothing was tried against a real model; the front end has no automated tests.

With 2.3 `ask._stem` no longer cuts "speed" to "spe". ### 6.4 Patterns

- **Build DOM with `h(tag, attrs, ...kids)`.** Text goes in as text nodes. Never use `innerHTML` with document or note text.
- **A page function** takes the root element, appends its section, and may return a cleanup function. The router calls the cleanup before the next page.
- **Saving.** Edits are sent as they happen. Typing uses `debounce()`; `flushPending()` runs on route change and page close.
- **Routing.** `route()` in `main.ts` splits the hash into `view`, `id`, `extra` and query parameters. `PART_OF` says which menu entry a page belongs to.
- **Styles.** One file, `web/static/styles.css`. Later blocks are appended under "Part" comments and override earlier ones. Panels use the `.isle` class and theme colours come from CSS variables.

## 7. Themes

A theme is a folder in `themes/`: `theme.json` with light and dark colour tokens, and an optional `scene.js` that default-exports a function returning `{ frame(dt), resize?(), destroy?() }`. `ambience.ts` owns the canvas, the frame rate (20 or 30 a second), pausing when hidden, and Still mode. A scene reads live state such as reading progress and cards reviewed.

`tests/test_themes.py` enforces the rules: text colours pass 4.5:1 contrast (also on see-through panels), and scenes use no network, no `eval`, no storage and no DOM writes.

## 8. Safety and reliability, and where each lives

| Rule | Where |
|---|---|
| Listen only on `127.0.0.1`, on a random port bound once and handed to uvicorn (never free in between); only `__main__.py` imports `socket` and `webbrowser`, and no module imports `ssl` or `subprocess` | `__main__.bind`; `tests/test_no_network.py` (`LOW_LEVEL`) |

| A file dropped outside a drop zone does not open as the window | `boot()` in `main.ts` |
| Sealed web lectures (`sandbox allow-scripts`, no network) | `lectures.SANDBOX_CSP` |
| One connection only: a network client is imported in `readhold/ai/adapters.py` and nowhere else in `readhold/`, and the front end only talks to its own server | `tests/test_no_network.py` |

| An API key lives only in the OS credential store; the API says only whether one is set; a key-shaped setting value is refused | `ai/keys.py`, `ai/settings.py` |

| Every AI call: timeout, one retry at most, output cap, 2 at once, daily token budget, cancel | `ai/port.py` |

## 10. How to add things

**A feature with data**
1. Add `readhold/migrations/00NN_name.sql` with the standard columns.
2. Add `readhold/<name>.py` with pydantic models and `register(app, db)`; call it in `create_app()`.
3. Add its shapes to `web/src/types.ts` and a page in `web/src/views/`.
4. Add a route in `main.ts`, and an entry in `PART_OF` if it lives under an existing menu entry.
5. Write tests in `tests/test_<name>.py`, then run `uv run pytest` and `npm run build`.

**A setting**
Add its default to `DEFAULT_SETTINGS` in `server.py` (unknown keys are ignored on save), its type to `Settings` in `types.ts`, and a control in the Settings page in `views/misc.ts`. An AI setting (`ai_…`) also goes into `DEFAULTS` and `CHECKS` in `ai/settings.py`, so its value is checked before it is stored.

**A tab on a tabbed page**
Add it to the list in `views/libtabs.ts`, put the matching `…Head("id")` at the top of its page, and add its page name to `PART_OF`.

**A theme**
Copy a folder in `themes/`, change `theme.json`, and run `uv run pytest tests/test_themes.py`. It appears in Settings without any other change.

**Renamed (2026-11-26).** The app and its package were called Foothold until 2026-11-26. `config.home()` still reads `FOOTHOLD_HOME`, `config.db_path()` moves an old `foothold.db` (and its -wal and -shm files) to `readhold.db` once, `DB.daily_backup` prunes old `foothold-daily-*` backups with the new ones, `ai.keys.get` moves a key saved under "Foothold" to "Readhold", and Clear AI history removes old `foothold-ai-export-*` files. `tests/test_rename.py` checks each, and that the old name appears nowhere else in the code.
